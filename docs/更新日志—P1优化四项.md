# 更新日志 — P1 优化四项

## 功能概述

P0 四项落地后继续推进的中优先级优化项：

1. **OCR 扫描页转写**：无文本层的扫描页（字符量 < 50）自动路由到 qwen-vl 多模态 OCR，PyMuPDF 渲染 → 转写纯文本
2. **表格结构化提取**：PDF（pdfplumber）与 docx（python-docx）表格转 Markdown 独立分片，超长表格按行切分并重复表头
3. **.doc 友好报错**：上传 .doc 旧格式单独提示"另存为 .docx 再上传"，不再显示笼统的格式不支持

**改前：** 扫描版 PDF 解析结果为空或残缺；表格文字混入正文被字符切分打碎（行列关系丢失，检索"CPU 阈值"对不上"90%"）；.doc 上传只报"不支持的文件格式"。
**改后：** 三项全部落地，均带降级保证（OCR 失败跳过该页、表格检测失败按无表格处理），核心链路零侵入。

---

## P1-1：OCR 扫描页转写

### 原理（文本密度路由）

pypdf 对扫描页提取不到文字（无文本层，只有图片）。以**单页有效字符数**为路由依据：低于 `ocr_min_text_chars`（默认 50）判定为扫描页，走 OCR 通道。

```
每页判定（_parse_pdf 三通道）:
  len(text) < 50  →  通道1: OCR（PyMuPDF 渲染 PNG → qwen-vl 转写）
  页内有表格      →  通道2: pdfplumber 表格提取（P1-2）
  其余           →  通道3: pypdf 快路径（P0 行为不变）
```

OCR 转写提示词要求**纯转写不解释**，遇表格输出 Markdown（保留结构信息）。

### 改动位置

**`app/services/ocr_service.py`（新增）：**

```python
# 延迟初始化 OpenAI 兼容客户端（复用 DashScope Key + timeout）
OpenAI(api_key=..., base_url=..., timeout=config.ocr_timeout)

# 渲染：PyMuPDF get_pixmap(dpi=150)，A4 约 1240x1754，OCR 足够且体积可控
# 转写：qwen-vl-max，PNG base64 作为 image_url + 纯转写提示词
# 失败/超时/空结果 → 返回空串（调用方跳过该页，等同旧版无 OCR 行为）
```

**`app/config.py`：**

```python
ocr_enabled: bool = True          # 总开关：False 时扫描页直接跳过（等同旧行为）
ocr_model: str = "qwen-vl-max"    # 多模态模型
ocr_timeout: float = 60.0         # 单页请求超时（秒）
ocr_min_text_chars: int = 50      # 低于此值判定为扫描页
```

### 降级保证

- OCR 单页失败 → 跳过该页，不阻塞整体解析（`ocr_page` 内部 try-except 全捕获）
- `ocr_enabled=False` → 完全回到 P0 行为
- 扫描页不走表格通道（无文本层检测不到表格，OCR 提示词已要求表格输出 Markdown）

### 已知取舍

- 逐页串行 OCR：百页扫描件解析耗时显著增加（每页 1 次 qwen-vl 调用）。运维场景文档页数可控，暂不并行；上传是低频操作，可接受

## P1-2：表格结构化提取

### 原理（标记抽离 + 独立分片）

表格被字符切分打碎的根因：表格 Markdown 跨越 1600 字符边界时，行列关系被切断（"CPU | 90%" 拆到两个 chunk，检索时对不上）。解法与 P0 页码标记同构——**提取层打标记，分片层抽离**：

```
提取层: [[TABLE]]\n| a | b |\n|---|---|\n| 1 | 2 |\n[[/TABLE]]
    ↓ 分片层（字符切分之前）
_extract_table_blocks: 正则抽离表格块（返回 "\n" 占位，表格不参与切分）
    ↓
_build_table_chunks: 每个表格一个独立 Document（_type=table 元数据）
```

**PDF 正文去重**：表格页的表格文字若同时出现在正文提取中会重复入库。用 pdfplumber 的 `outside_bbox` 剔除表格区域后再提取正文：

```
body = plumber_page.outside_bbox(table.bbox).extract_text()
```

**docx 章节上下文**：docx 表格按文档顺序遍历（CT_P / CT_Tbl 交替），表格附带前方最近的章节标题（`（所属章节: xxx）`）——表格脱离标题语义会失真（"阈值表"三个字不在表格里，检索"阈值"就找不到）。

### 改动位置

| 位置 | 改动 |
|---|---|
| `document_parser_service.py` `_parse_pdf` | 通道2：`_find_pdf_tables`（异常降级返回空）→ `_pdf_text_without_tables`（正文剔除表格区域）→ 表格转 Markdown 包 `[[TABLE]]` 标记 |
| `document_parser_service.py` `_parse_docx` | 按文档顺序遍历段落 + 表格；表格转 Markdown + 章节上下文 |
| `document_parser_service.py` `_rows_to_markdown` | 二维数据 → Markdown；单元格规整化（None→空串、管道符转义 `\|`、换行合并空格）；<2 行或 <2 列的误检（分隔线/装饰框）返回空串；行列不齐自动补齐 |
| `document_splitter_service.py` `_extract_table_blocks` | 正则抽离表格块（PDF 表格通过前方最近 `[[PAGE:n]]` 关联页码） |
| `document_splitter_service.py` `_build_table_chunks` | 独立分片构造；超过 `_MAX_TABLE_CHUNK_CHARS`（7000）按行切分，**每片重复表头**（前两行）+ `_table_part: n/m` 元数据 |
| `config.py` | `pdf_table_extraction_enabled: bool = True` 总开关 |

### 降级保证

- 表格检测异常 → 本页按无表格处理（走通道3 纯文字）
- `pdf_table_extraction_enabled=False` → PDF 完全回到 P0 行为
- 误检过滤：<2 行或 <2 列的"表格"（大概率是分隔线/边框装饰）丢弃
- 超长表格：按行切分保住行列结构（每片含表头），比字符切分打碎强

### 收益

- 表格 chunk 的行列结构完整 → "查 CPU 告警阈值" 能命中表格行
- `_type=table` + 页码元数据 → 检索引用可标注"来自第 N 页的表格"
- 正文与表格去重 → 同一数据不再双份入库

## P1-3：.doc 友好报错

### 改动位置

**`app/api/file.py`：**

```python
# .doc（Word 97-2003 二进制）单独提示，其余不支持格式走通用报错
if file_extension == "doc":
    raise HTTPException(400, detail="检测到 .doc 旧格式（Word 97-2003 二进制格式），"
                                     "暂不支持。请用 Word 打开后另存为 .docx 再上传")
```

不做服务端自动转换（需引入 LibreOffice 依赖，部署成本高）；运维文档量可控，用户手动另存即可。
