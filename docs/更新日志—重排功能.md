# 更新日志 — 重排功能

## 功能概述

在 RAG（检索增强生成）流程中增加了**重排（Rerank）**步骤，提升最终生成回答的质量和相关性。

## 原有流程

```
用户问题 → 向量检索(top_k=3) → 直接生成回答
```

问题：向量检索只返回 3 条，精度不够，可能漏掉更相关的文档。

## 新流程（三段式）

```
用户问题 → 1.召回(向量检索 top_k=10) → 2.重排(Rerank) → 3.生成(选 top-3 + LLM)
```

### 1. 召回（Retrieval）
- 将用户问题向量化，去 Milvus 向量数据库进行 ANN 相似度搜索
- 查询最相似的 **10 个**片段（`RAG_TOP_K=10`）
- 特点：**快但准度低**，用向量近似搜索快速召回候选文档

### 2. 重排（Rerank）
- 使用阿里云百炼平台的 `qwen3-rerank` 模型（原 `gte-rerank` 已于 2026-05-30 下线）
- 逐对计算用户问题与每个召回片段的语义相关性（Cross-encoder 架构）
- 按相关性分数降序排列，选取 top-3
- 特点：**慢但准度高**，用精确的语义匹配模型精排

### 3. 生成（Generation）
- 从重排结果中选出最相关的 **3 个**片段
- 将 3 个片段 + 用户问题一起交给大模型
- 大模型根据提供的片段进行回答

## 修改的文件

### 1. `app/config.py`
- `rag_top_k` 从 `3` 改为 **`10`** — 召回阶段查更多文档供重排
- 新增 `rag_rerank_top_k: int = 3` — 重排后保留的文档数
- 新增 `rag_rerank_model: str = "qwen3-rerank"` — 百炼 rerank 模型名

### 2. `.env`
- `RAG_TOP_K` 从 `3` 改为 `10`
- 新增 `RAG_RERANK_TOP_K=3`
- 新增 `RAG_RERANK_MODEL=qwen3-rerank`

### 4. `app/tools/knowledge_tool.py`
`retrieve_knowledge` 函数的核心流程变更：

**修改前：**
```
向量检索(top_k=3) → format_docs() → 返回
```

**修改后：**
```
向量检索(top_k=10) → rerank_service.rerank(query, docs, top_k=3) → format_docs() → 返回
```

`format_docs()` 新增：在参考资料标题旁显示 `(相关性: x.xxxx)` 重排分数

## 技术细节

### API 调用方式
- URL: `https://dashscope.aliyuncs.com/compatible-api/v1/reranks`
- 认证: `Authorization: Bearer <DASHSCOPE_API_KEY>`
- 超时: 60 秒
- 请求体:
  ```json
  {
    "model": "qwen3-rerank",
    "query": "用户问题",
    "documents": ["文档1内容", "文档2内容", ...],
    "top_n": 3
  }
  ```

### 降级策略
- 如果 rerank API 超时或返回错误，自动降级为使用原始向量检索结果（`documents[:top_k]`）
- 不影响用户正常使用

## 验证方法

启动应用后，在对话中输入问题，观察日志：
- `Rerank 开始: query='...', 输入文档数=N, top_k=3`
- `Rerank 完成: 输出文档数=N`
- `重排阶段: 从 10 条中精选 top-3`

如果 rerank 成功，每个参考资料旁会显示 `(相关性: 0.xxxx)` 的分数。
