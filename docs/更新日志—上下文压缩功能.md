# 更新日志 — 上下文压缩功能

## 功能概述

在长对话和 RAG 多轮检索场景中，当 token 使用量达到 qwen-max 上下文窗口（128K）的 **70%** 时，自动触发大模型摘要压缩旧对话，保留最近 **3 轮** 原文。避免上下文窗口被撑爆，同时保留关键对话信息。

## 为什么需要这个功能

### 原来的 3 个问题

**问题 1：对话历史无限增长**
每轮对话的消息都存储在 MemorySaver 中，从不清理。
```
第 1 轮：[sys, user1, ai1]
第 10 轮：[sys, user1, ai1, sys, user2, ai2, ..., sys, user10, ai10]
第 30 轮：约 30 条消息 + 30 份 RAG 参考文档 ≈ 90K tokens → ❌ 快撑爆 128K
```

**问题 2：系统提示词重复发送**
每次 `query()` 都传入 `SystemMessage`，但 LangGraph 的 `add_messages` 是追加不是替换。
```
实际存储： [sys, user1, ai1, sys, user2, ai2, sys, user3, ai3, ...]
                                                ^^^  ^^^  ^^^  每轮多一份！
```
等于每轮对话都在浪费 ~200 tokens × N 轮的 system prompt token。

**问题 3：RAG 多轮检索叠加**
每轮 RAG 检索带回 3 个参考文档（~2400 tokens），多轮对话更是加速撑爆上下文。

### token 消耗估算

| 项目 | 单轮 token 数 |
|---|---|
| 用户问题 | ~100 |
| AI 回答 | ~300 |
| RAG 参考文档 (3×800) | ~2,400 |
| **合计** | **~2,800** |

128K × 70% ≈ **~90K** → 约 **32 轮** 后触发压缩

## 实现原理

### 使用 LangChain 内置的 SummarizationMiddleware

LangChain **1.2.10** 已经内置了 `langchain.agents.middleware.SummarizationMiddleware`，我们直接使用，不重复造轮子。

### 它是如何工作的？

SummarizationMiddleware 是一个 **AgentMiddleware**，在 agent 每次调用 LLM **之前**（`before_model` 钩子）检查消息的 token 总量：

```
┌─ agent.ainvoke({"messages": [...]})
│
├─ [SummarizationMiddleware.before_model()]
│   │
│   ├─ 1. 计算当前消息总 token
│   │   → model.get_num_tokens_from_messages(state["messages"])
│   │
│   ├─ 2. 计算占比：total / 131072 ≥ 0.7 ?
│   │
│   ├─ 否 (< 70%) → 什么都不做，正常流程
│   │
│   └─ 是 (≥ 70%) → 触发压缩
│       │
│       ├─ ① 确定安全截断点
│       │   （保证 AI/Tool 消息对完整，不会在 tool call 中间截断）
│       │
│       ├─ ② 分割消息
│       │   ├─ 旧消息 = messages[:-6]（需要摘要压缩的）
│       │   └─ 保留消息 = messages[-6:]（最近 3 轮 = 6 条）
│       │
│       ├─ ③ 调用大模型生成摘要
│       │   → "Summarize the following conversation history..."
│       │
│       ├─ ④ 构建新消息列表
│       │   → [摘要消息] + [最近 6 条保留消息]
│       │
│       └─ ⑤ 返回 RemoveMessage + 新列表
│           → checkpointer 中的状态被永久替换
│
├─ Agent 节点（LLM 决策回答还是调用工具）
├─ Tool 节点（执行 RAG 检索等工具）
└─ 最终生成回答 → 返回给用户
```

### 关键参数

```python
SummarizationMiddleware(
    model=self.model,                              # ChatQwen(qwen-max) 用于摘要
    trigger=("fraction", 0.7),                     # 上下文 70% 时触发
    keep=("messages", 6),                          # 保留最近 6 条消息（3 轮）
)
```

**trigger 的多种模式：**

| 模式 | 示例 | 说明 |
|---|---|---|
| `("fraction", 0.7)` | 上下文占比 | **推荐**。自动适配任何模型的上下文窗口 |
| `("tokens", 90000)` | 固定 token 数 | 总 token ≥ 90,000 时触发 |
| `("messages", 50)` | 消息条数 | 消息 ≥ 50 条时触发 |
| `[("fraction", 0.8), ("messages", 100)]` | 组合 OR | 任一条件满足即触发 |
| `{"tokens": 5000, "messages": 10}` | 组合 AND | 两个条件都满足才触发 |

### 为什么用 LangChain 内置的而不是自己实现？

1. **省代码**：已经处理了安全截断点（AI/Tool 消息对完整性）、token 计数、摘要 prompt 等复杂逻辑
2. **省维护**：LangChain 社区维护，已有 bug 修复（如 token 膨胀问题 #34607）
3. **开箱即用**：三行代码搞定
   ```python
   from langchain.agents.middleware import SummarizationMiddleware
   middleware = SummarizationMiddleware(model=model, trigger=("fraction", 0.7), keep=("messages", 6))
   create_agent(..., middleware=[middleware])
   ```

## 修改的文件

### 1. `app/config.py`

```python
# RAG 配置
rag_top_k: int = 10

# 重排（Rerank）配置
rag_rerank_top_k: int = 3
rag_rerank_model: str = "qwen3-rerank"

# 上下文压缩配置（新增）
rag_context_window_size: int = 131072       # qwen-max 上下文窗口（128K tokens）
rag_compression_threshold: float = 0.7      # 触发压缩的 token 占比阈值
rag_keep_recent_rounds: int = 3             # 保留最近几轮完整原文
rag_compression_model: str = "qwen-max"     # 压缩用的模型
```

### 2. `.env`

```ini
# 上下文压缩配置（新增）
RAG_CONTEXT_WINDOW_SIZE=131072
RAG_COMPRESSION_THRESHOLD=0.7
RAG_KEEP_RECENT_ROUNDS=3
RAG_COMPRESSION_MODEL=qwen-max
```

### 3. `app/services/rag_agent_service.py` — 核心修改

#### 改动点 A：增加导入

```python
from langchain.agents.middleware import SummarizationMiddleware  # 新增
```

#### 改动点 B：注入中间件到 agent

**改前：**
```python
self.agent = create_agent(
    self.model,
    tools=all_tools,
    checkpointer=self.checkpointer,
)
```

**改后：**
```python
summarization_middleware = SummarizationMiddleware(
    model=self.model,
    trigger=("fraction", config.rag_compression_threshold),
    keep=("messages", config.rag_keep_recent_rounds * 2),
)

self.agent = create_agent(
    self.model,
    tools=all_tools,
    checkpointer=self.checkpointer,
    system_prompt=self.system_prompt,         # 新增：让 LangChain 托管 system prompt
    middleware=[summarization_middleware],     # 新增：注入压缩中间件
)
```

#### 改动点 C：修复 system prompt 重复 bug

**改前（query + query_stream）：**
```python
messages = [
    SystemMessage(content=self.system_prompt),
    HumanMessage(content=question)
]
```

**改后：**
```python
# system prompt 由 agent 托管（create_agent 时注入），无需重复传入
messages = [HumanMessage(content=question)]
```

## 验证方法

启动应用后，与 AI 进行多轮对话验证。

### 测试场景

**场景 1：正常短对话**
- 问 2-3 个简单问题
- 预期：正常回答，不触发压缩

**场景 2：长对话触发压缩**
- 连续问 30+ 轮问题（尽量带 RAG 检索）
- 预期：约第 30 轮后 SummarizationMiddleware 自动触发摘要压缩
- 观察日志（若 LOG_LEVEL=DEBUG 可以看到 LangChain 内部调试日志）：

```
SummarizationMiddleware: Triggering summarization (token count: 92000, threshold: 91750)
SummarizationMiddleware: Keeping 6 messages, summarizing N messages
```

**场景 3：验证 system prompt 不再重复**
- 观察 `/api/chat/sessions` 返回的历史记录
- 改前：历史中有 N 份 SystemMessage
- 改后：历史中只有 1 份 SystemMessage（由 agent 托管）

### 故障排查

| 症状 | 可能原因 | 解决 |
|---|---|---|
| Agent 启动失败 | SummarizationMiddleware 初始化需 model profile | 检查 langchain 版本 ≥ 1.2.10 |
| 压缩未触发 | 对话轮数不够，未达阈值 | 继续多轮对话 |
| 压缩太频繁 | threshold 太低 | 调高到 0.75 或 0.8 |
| 压缩太少 | threshold 太高 | 调低到 0.6 |
