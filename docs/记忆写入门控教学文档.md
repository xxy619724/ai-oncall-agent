# 记忆写入门控教学文档（从零讲起）

> 本文档假设你是一个刚接触 Agent 记忆工程的学生，会用最简单的语言，一步步教你理解「写入门控」是什么、为什么需要、代码怎么写。

---

## 一、先搞懂：什么是「记忆」和「写入」？

### 1.1 Agent 的记忆是什么？

想象 Agent 是一个客服员工。每次用户来咨询，他需要：
- 记住用户说了什么（**短期记忆**）
- 记住用户的长期偏好，比如"喜欢中文回复"（**长期记忆**）

我们的项目里，Agent 完成任务后，会把**任务经验**（任务是什么、怎么解决的、踩了什么坑）写入长期记忆，下次遇到相似任务就能复用。

### 1.2 什么是「写入」？

「写入」就是把经验保存到数据库里。我们的项目用两个地方存：
- **Milvus**（向量数据库）：存经验文本的向量，用于语义检索（下次相似任务能搜到）
- **SQLite**（关系数据库）：存结构化数据（任务、方案、步骤、错误），用于审计查证

### 1.3 什么是「门控」？

「门控」就是写入前的**检查站**。就像进门要过安检：
- 不是所有东西都能带进去（查重）
- 带进去的东西不能和已有的冲突（冲突检测）
- 不确定的东西要先标记待确认（置信度评估）

**没有门控的问题**：重复经验堆积、矛盾经验并存、幻觉内容污染记忆库。

## 二、改造前：我们的门控长什么样？

### 2.1 改造前的代码（只有最基础的门控）

```python
# 改造前：只有"有/无"判断
async def memory_writer(state):
    input_text = state.get("input", "")
    response = state.get("response", "")

    # 门控：输入或响应为空就跳过
    if not input_text or not response:
        return {}

    # 直接写入，没有任何检查
    await _write_to_milvus(...)
    await _write_to_sqlite(...)
```

### 2.2 改造前的问题

| 问题 | 说明 | 后果 |
|------|------|------|
| 没有查重 | 同一任务执行多次，每次都写入 | 重复经验堆积，浪费存储 |
| 没有冲突检测 | 新经验和旧经验矛盾 | 检索时两条都返回，模型困惑 |
| 没有置信度 | 模型幻觉的内容也写入 | 错误经验污染记忆库 |
| 没有元数据 | 缺置信度、状态、TTL | 无法做软删除、过期清理 |

## 三、改造后：四步门控流程

### 3.0 整体流程图

```
任务执行完成，生成 response
        ↓
  ① 门控1：输入/响应非空？
        ↓ 是
  ② 门控2：查重（相似度 ≥ 0.95？）
        ├── 是 → 跳过写入（已有相同经验）
        └── 否 ↓
  ③ 门控3：冲突检测（相似度 0.80~0.95？）
        ├── 有冲突 → 旧经验标记 deprecated（软删除）
        └── 无冲突 ↓
  ④ 门控4：置信度评估
        ├── high（工具数据）→ status=active
        ├── medium（模型推理）→ status=active
        └── low（外部工具）→ status=pending（待确认）
        ↓
  ⑤ 正式写入 Milvus + SQLite（携带完整元数据）
```

### 3.1 门控1：基础检查（输入/响应非空）

**原理**：如果任务没有输入或没有生成最终方案，就没有经验可写。

```python
# 代码位置：memory_writer.py 第 386-389 行
input_text = state.get("input", "")
response = state.get("response", "")

if not input_text or not response:
    logger.warning("输入或响应为空，跳过经验回写")
    return {}
```

**讲解**：
- `state.get("input", "")`：从 LangGraph 的 State 里取用户输入，如果没有就返回空字符串
- `return {}`：返回空字典，表示不修改 State（纯副作用节点）

---

### 3.2 门控2：查重（写入前检查是否已有相似经验）

**原理**：写入前先用任务文本去 Milvus 检索，看是否已存在高度相似的经验。如果相似度 ≥ 0.95，说明是重复任务，跳过写入。

**配置项**（config.py 第 78-79 行）：
```python
memory_dedup_threshold: float = 0.95     # 查重阈值（≥0.95 判定重复）
memory_conflict_threshold: float = 0.80  # 冲突检测阈值（≥0.80 进入冲突检测）
```

**代码**（memory_writer.py 第 128-183 行）：
```python
async def _check_duplicate(input_text, dedup_threshold):
    """查重：检索是否已存在相似经验"""
    try:
        from app.services.vector_store_manager import vector_store_manager

        # 第1步：用任务文本在 Milvus 中做相似度检索
        # similarity_search_with_score 返回 [(文档, 分数), ...]
        # 分数范围 [0, 1]，越接近 1 越相似
        docs_with_scores = vector_store_manager.vector_store.similarity_search_with_score(
            input_text, k=3, param={"metric_type": "COSINE", "params": {"nprobe": 10}}
        )

        # 第2步：过滤，只看经验类文档（不看知识库文档）
        # _source == "aiops_experience" 表示是 Agent 自动沉淀的经验
        # _source 是文件路径表示是人工录入的知识库文档
        exp_with_scores = [
            (doc, score)
            for doc, score in docs_with_scores
            if doc.metadata.get("_source") == "aiops_experience"
        ]

        if not exp_with_scores:
            return False, []  # 没有相似经验，正常写入

        # 第3步：取最高分
        top_doc, top_score = exp_with_scores[0]

        # 第4步：判断
        if top_score >= dedup_threshold:
            # 相似度 ≥ 0.95 → 重复，跳过写入
            return True, exp_with_scores

        if top_score >= config.memory_conflict_threshold:
            # 相似度 ≥ 0.80 → 进入冲突检测
            return False, exp_with_scores

        # 相似度 < 0.80 → 无相似，正常写入
        return False, []

    except Exception as e:
        logger.error(f"查重失败: {e}")
        return False, []  # 查重失败不阻塞写入（容错）
```

**逐行讲解**：
- `similarity_search_with_score`：Milvus 的向量检索，返回文档和相似度分数
- `k=3`：最多返回 3 条
- `metric_type="COSINE"`：用余弦相似度计算
- `nprobe=10`：搜索精度参数，越大越精确但越慢
- 过滤 `_source == "aiops_experience"`：只看经验，不看知识库文档
- 返回值 `(is_duplicate, similar_docs)`：是否重复 + 相似文档列表

### 3.3 门控3：冲突检测（新旧经验是否矛盾）

**原理**：如果新经验和旧经验高度相似但不完全重复（0.80 ≤ 相似度 < 0.95），检查是否矛盾。矛盾时旧经验标记为 `deprecated`（废弃），新经验正常写入。

**代码**（memory_writer.py 第 186-222 行）：
```python
async def _detect_conflict(new_input, new_response, new_has_error, old_doc):
    """冲突检测：新经验与旧经验是否矛盾"""

    old_metadata = old_doc.metadata
    old_has_error = old_metadata.get("has_error", False)

    # 规则1：has_error 不同（旧无错误但新有错误，或反之）
    if old_has_error != new_has_error:
        return True, f"has_error 不同: 旧={old_has_error}, 新={new_has_error}"

    # 规则2：response 关键词矛盾
    old_preview = old_metadata.get("task_preview", "")
    contradiction_pairs = [
        ("正常", "异常"),
        ("成功", "失败"),
        ("正常", "错误"),
        ("通过", "拒绝"),
    ]
    for pos, neg in contradiction_pairs:
        if pos in old_preview and neg in new_response:
            return True, f"response 矛盾: 旧含'{pos}', 新含'{neg}'"
        if neg in old_preview and pos in new_response:
            return True, f"response 矛盾: 旧含'{neg}', 新含'{pos}'"

    return False, ""
```

**讲解**：
- `has_error`：旧经验有没有错误步骤，新经验有没有错误步骤，如果不同说明矛盾
- `contradiction_pairs`：关键词对，如果旧经验说"正常"但新经验说"异常"，就是矛盾
- 返回 `(is_conflict, reason)`：是否冲突 + 冲突原因

**冲突后标记旧经验**（memory_writer.py 第 225-250 行）：
```python
async def _mark_old_deprecated(sqlite_conn, old_doc):
    """标记旧经验为 deprecated（软删除）"""
    old_id = old_doc.metadata.get("experience_id")

    # 在 SQLite 中更新 status=deprecated
    # 不物理删除，保留审计记录
    await sqlite_conn.execute(
        "UPDATE aiops_experiences SET status = 'deprecated' WHERE id = ?",
        (old_id,),
    )
    await sqlite_conn.commit()
```

**讲解**：
- 软删除：不物理删除数据，只标记 `status=deprecated`
- 好处：保留历史记录，可以审计复盘；检索时过滤掉 deprecated 的就行
- 对比硬删除：直接 DELETE，数据彻底丢失，无法追溯

### 3.4 门控4：置信度评估

**原理**：不同来源的信息可信度不同：
- 工具返回的确定性数据（如 Prometheus 查询结果）→ **high**（可信）
- 纯模型推理（LLM 生成的结论）→ **medium**（一般可信）
- 外部工具返回（MCP/第三方接口）→ **low**（不可全信）

低置信度的经验标记 `status=pending`（待确认），不立即激活。

**代码**（memory_writer.py 第 91-125 行）：
```python
# 外部工具关键词（用于识别低置信度来源）
_EXTERNAL_TOOL_KEYWORDS = ("mcp", "外部", "第三方", "接口调用", "api")

def _assess_confidence(past_steps, response):
    """评估经验置信度"""
    has_tool_success = False
    has_external = False

    for step, result in past_steps:
        result_str = result if isinstance(result, str) else str(result)
        result_lower = result_str.lower()

        # 检查是否含外部工具关键词
        if any(kw in result_lower for kw in _EXTERNAL_TOOL_KEYWORDS):
            has_external = True
            break  # 外部来源直接 low，不用继续

        # 检查是否含工具调用成功结果（非错误）
        if not any(kw in result_lower for kw in _ERROR_KEYWORDS):
            has_tool_success = True

    if has_external:
        return "low"
    elif has_tool_success:
        return "high"
    else:
        return "medium"
```

**讲解**：
- 遍历 `past_steps`（执行历史），检查每一步的结果
- 如果结果里包含 "mcp"、"外部" 等关键词 → 低置信度
- 如果结果里没有错误关键词 → 说明工具调用成功了 → 高置信度
- 否则 → 中置信度（纯模型推理）

**在 memory_writer 节点中使用**：
```python
# 门控4：置信度评估
confidence = _assess_confidence(past_steps, response)

# 低置信度标记 pending（待确认），不立即激活
status = "pending" if confidence == "low" else "active"
```

## 四、完整门控流程（memory_writer 节点）

**代码位置**：memory_writer.py 第 373-474 行

```python
async def memory_writer(state):
    """经验回写节点：把任务经验写入 LTM

    门控流程：查重 → 冲突检测 → 置信度评估 → 写入
    """
    input_text = state.get("input", "")
    past_steps = state.get("past_steps", [])
    response = state.get("response", "")

    # ===== 门控1：输入或响应为空，跳过 =====
    if not input_text or not response:
        return {}

    # ===== 门控2：写入前查重 =====
    is_duplicate, similar_docs = await _check_duplicate(
        input_text, config.memory_dedup_threshold  # 0.95
    )
    if is_duplicate:
        return {}  # 重复，跳过

    # ===== 门控3：冲突检测 =====
    if similar_docs:
        new_has_error = len(_extract_errors(past_steps)) > 0
        for old_doc, score in similar_docs:
            is_conflict, reason = await _detect_conflict(
                input_text, response, new_has_error, old_doc
            )
            if is_conflict:
                # 旧经验标记 deprecated（软删除）
                await _mark_old_deprecated(sqlite_conn, old_doc)

    # ===== 门控4：置信度评估 =====
    confidence = _assess_confidence(past_steps, response)
    status = "pending" if confidence == "low" else "active"

    # ===== 提取错误 + 构建经验摘要 =====
    errors = _extract_errors(past_steps)
    experience_text = _build_experience_text(input_text, response, errors, past_steps)

    # ===== 正式写入 =====
    await _write_to_milvus(experience_id, experience_text, ...)
    await _write_to_sqlite(sqlite_conn, experience_id, ...)
```

## 七、status 状态流转

```
写入时：
  confidence=high/medium → status=active（正常激活）
  confidence=low         → status=pending（待确认）

冲突时：
  旧经验 → status=deprecated（废弃，不删除）

未来扩展（待实现）：
  pending → 用户确认 → status=active
  pending → 用户否决 → status=rejected
  active → 超过TTL → status=deprecated → 定时清理 → 物理删除
```

## 九、总结：一句话理解

**改造前**：有 input 和 response 就直接写入（0/1 门控）。

**改造后**：四步门控 —— 查重（≥0.95 跳过）→ 冲突检测（旧经验标记 deprecated）→ 置信度评估（low 标记 pending）→ 携带完整元数据写入。

**核心价值**：防止重复存储、矛盾并存、幻觉污染，让记忆库更干净、更可信、更可审计。
