# 更新日志 — P0 优化四项

## 功能概述

针对文档解析与对话链路的四个高优先级优化项落地：

1. **Word 标题结构化切分**：docx 标题样式（Heading 1/2）映射为 Markdown 标记，复用标题切分链路
2. **PDF 页码元数据**：chunk 携带页码范围（`_page_start`/`_page_end`），检索引用可溯源到页
3. **主动终止接口**：`POST /chat/stop`，流式输出中可随时停止，前端发送按钮变为停止按钮
4. **断网问题暂存**：提问先存 localStorage，请求成功后清除；断网刷新后恢复到输入框手动重发

**改前：** Word 只走字符切分（标题信息丢弃）；PDF 无页码信息（引用只能到文件名）；流式输出无法主动停止（只能等生成完或断开连接）；断网后问题丢失需重新输入。
**改后：** 四项全部落地，均带降级保证，不引入新依赖。

## P0-1：Word 标题结构化切分

### 原理

python-docx 提取段落时，段落对象的 `style.name` 携带样式信息（`Heading 1` / `标题 1` 等）。改前只取 `p.text`，标题层级信息被丢弃，Word 文档只能走字符切分。

改后在**提取层**把标题样式翻译成 Markdown 标记，**分片层**零新增逻辑直接复用现有 Markdown 链路：

```
docx 段落 (style=Heading 1, text=CPU排查)
    ↓ 提取层映射
"# CPU排查"
    ↓ 复用现有链路
MarkdownHeaderTextSplitter(h1/h2) → RecursiveCharacterTextSplitter(1600/100) → 合并小片段
```

### 改动位置

**`app/services/document_parser_service.py`：**

```python
# _parse_docx: 段落按样式映射为 Markdown 标记
for p in doc.paragraphs:
    text = p.text.strip()
    if not text:
        continue
    prefix = self._docx_heading_prefix(p.style.name if p.style else "")
    lines.append(f"{prefix}{text}" if prefix else text)

# 新增 _docx_heading_prefix: 样式名 → Markdown 前缀
"Heading 1" / "标题 1"  →  "# "
"Heading 2" / "标题 2"  →  "## "
其他                     →  ""    # 正文，不加标记
```

只映射 H1/H2 两级，与 Markdown 分片策略对齐（不按 H3 切，避免过度碎片化）。

**`app/services/document_splitter_service.py`：**

```python
# split_document 路由: docx 加入 Markdown 链路
if file_path.endswith(".md"):
    docs = self.split_markdown(content, file_path)
elif file_path.endswith(".docx"):
    docs = self.split_markdown(content, file_path)  # 复用标题切分
else:
    docs = self.split_text(content, file_path)
```

同时修复 `split_markdown` 中硬编码 `_extension = ".md"` 的 bug（docx 复用此链路时会被误标），改为 `Path(file_path).suffix`。

### 降级保证

无标题样式的 docx：MarkdownHeaderTextSplitter 找不到标题 → 整体走 RecursiveCharacterTextSplitter，行为与改前完全一致。

### 收益

- docx chunk 的 metadata 携带 `h1`/`h2` 标题链 → 检索引用展示章节标题（`format_docs` 已有逻辑直接生效）
- 切分边界与文档结构对齐，语义完整性提升

## P0-2：PDF 页码元数据

### 原理（文本标记法）

pypdf 逐页提取时天然有页码。采用**文本标记法**：提取层在每页文本前插入 `[[PAGE:n]]` 标记，标记随文本流经切分器（跨页内容不会被强制切断，保住 RAG 质量），分片完成后从每个 chunk 中提取页码范围写入 metadata，并从正文中清除标记。

```
[[PAGE:1]]第一页文本 [[PAGE:2]]第二页文本
    ↓ 切分（标记随文本流动，跨页 chunk 同时含两个标记）
chunk: "...[[PAGE:1]]...部分文本...[[PAGE:2]]...部分文本..."
    ↓ _extract_page_metadata
metadata: {_page_start: 1, _page_end: 2}, 正文无标记
```

**为什么不用"按页独立切分"**：页码虽然天然准确，但跨页的章节会被强制在页边界切断，损害检索质量。标记法两者兼得。

### 改动位置

**`app/services/document_parser_service.py` `_parse_pdf`：**

```python
for i, page in enumerate(reader.pages, start=1):
    text = page.extract_text()
    if text.strip():
        pages_text.append(f"[[PAGE:{i}]]\n{text}")  # 每页前插页码标记
```

**`app/services/document_splitter_service.py`：**

```python
# 模块级正则
_PAGE_MARKER_RE = re.compile(r"\[\[PAGE:(\d+)\]\]")      # 完整标记（提取页码）
_PAGE_MARKER_ANY_RE = re.compile(r"\[\[PAGE:\d*\]*")     # 含半截标记（兜底清除）

# split_document 末尾：仅对 .pdf 生效（避免误伤其他类型文档中的同形文本）
if file_path.endswith(".pdf"):
    docs = self._extract_page_metadata(docs)

# 新增 _extract_page_metadata:
#   1. 完整标记 → _page_start = min(页码), _page_end = max(页码)
#   2. 清除完整标记 + 兜底清除被切分器截断的半截标记（如 "[[PAGE:12"）
#   3. 清理后为空的分片（纯标记无正文）直接丢弃
```

**`app/tools/knowledge_tool.py` `format_docs`：**

```python
# 检索引用自动带页码
来源: cpu排查手册.pdf (第3-5页)
```

### 降级保证

- 半截标记（极端情况下切分器切在标记中间）：正则兜底清除，该 chunk 无页码字段，不影响入库
- 纯标记分片：丢弃，避免空内容入库
- 非 PDF 类型：不执行页码提取，`.md`/`.txt`/`.docx` 中的同形文本不受影响

## P0-3：主动终止接口

### 原理（停止标记位）

SSE 响应由 `EventSourceResponse` 驱动，服务端拿不到驱动 task，Task cancel 方案侵入性大。采用**停止标记位**：

```
前端点停止 → POST /chat/stop {sessionId}
    ↓
rag_agent_service.request_stop(session_id)
    → _stop_flags[session_id].set()          # asyncio.Event 注册表
    ↓
query_stream 的 token 循环（每个 token 检查一次）
    → stop_event.is_set() → break
    → yield {"type": "stopped"}              # 通知前端
    → finally: 注册表清理，防内存泄漏
```

终止粒度为 token 边界（相邻 token 间隔通常 <100ms），实际感知为立即停止。

### 改动位置

| 文件 | 改动 |
|---|---|
| `app/services/rag_agent_service.py` | 新增 `_stop_flags` 注册表；`query_stream` 注册/检查/清理停止标记，停止时 yield `stopped` 事件并跳过摘要同步；新增 `request_stop()` |
| `app/models/request.py` | 新增 `StopRequest`（`sessionId` 别名，与 `ClearRequest` 同构） |
| `app/api/chat.py` | 新增 `POST /chat/stop`；`event_generator` 新增 `stopped` 事件转发 |
| `static/app.js` | 流式中发送按钮变停止按钮（`stop-mode` 样式）；`stopGeneration()` 调停止接口 + `reader.cancel()` 中断本地读取；`stopped`/`done` 事件统一走 `handleStreamComplete`（`streamFinished` 防重入，避免重复写入历史） |
| `static/styles.css` | `.send-btn-circle.stop-mode` 停止按钮样式（红色方块图标） |

### 已知取舍

- 中途停止时该轮 AIMessage 不写入 checkpoint（LangGraph 按 super-step 边界保存），下一轮 LLM 会看到"未回答的问题"，可接受
- 停止后已生成的部分内容保留在前端展示并计入前端历史
- 快速模式（单次 POST）不支持停止：`canStop` 仅在 `stream` 模式生效

## P0-4：断网问题暂存

### 原理

```
发送前: localStorage.setItem('pending_question', 问题)
    ↓ 请求成功（含用户主动停止：问题已送达后端）
localStorage.removeItem('pending_question')
    ↓ 请求失败（断网/服务异常）
保留暂存 → 刷新页面 → restorePendingQuestion()
    → 恢复到输入框 + 通知提示 → 用户确认后手动重发
```

**为什么手动确认而非自动重发**：网络抖动恢复瞬间自动重发可能造成重复提交（重复扣 token 费用），恢复到输入框由用户确认是更安全的取舍。

### 改动位置

`static/app.js`：

- `sendMessage()`：发送前 `savePendingQuestion()`，成功后 `clearPendingQuestion()`，失败保留
- 构造函数：`restorePendingQuestion()` 页面加载时检测残留
- 三个新方法：`savePendingQuestion` / `clearPendingQuestion` / `restorePendingQuestion`

单一 key（`pending_question`）而非按 session 分 key：前端每次页面加载生成新 sessionId，旧 key 会成为孤儿数据；单 key 场景下恢复语义一致且无残留。
